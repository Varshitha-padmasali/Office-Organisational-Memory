# Migrations

**Status: set up as of Day 2.** Alembic is configured (`backend/alembic.ini`
+ `env.py` in this directory) and reads `DATABASE_URL` from
`app.core.config`, so it always targets whatever database is currently
configured — no URL is hardcoded here.

## Applying migrations

```bash
cd backend
alembic upgrade head
```

This runs, in order:
- `0001_create_users_table.py`
- `0002_create_documents_table.py`

## Creating a new migration

Once new models exist under `app/models/` (imported in `env.py`):

```bash
cd backend
alembic revision --autogenerate -m "create chunks table"
```

Always read the autogenerated file before running it — autogenerate is a
good first draft, not a guarantee (it won't detect every change, e.g.
some constraint renames).

## Rolling back

```bash
alembic downgrade -1     # one step back
alembic downgrade base   # all the way back (drops everything)
```

## Day 3+ note

The `chunks` table (with a `pgvector` embedding column) is intentionally
not created yet — see `docs/architecture.md` §5 for why the schema was
sequenced this way.
